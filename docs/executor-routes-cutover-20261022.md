### D Persistence API

All methods are nested Main methods, available to D's same-entry durable context:

```csharp
internal JSONObject ExportRouteExecutionCommitments();
internal void ImportRouteExecutionCommitments(JSONNode saved);
internal bool RebindRouteExecutionCommitments();
```

Import clones/quarantines the semantic record; it never imports claims, grants,
delegates, native references or cleanup authority. `Rebind...` is an EXPLICIT REVIEW
operation, not a frame callback. It checks rebirth/origin/elapsed/OS/W continuity,
exact selected equipment material/uniqueness, support and native settings. Missing
or uncertain finite-effect ledger evidence blocks rebind, not replay. An exact
supported route gets a fresh session claim with the SAME acquisition identifier.
Manual/tower death-log cursor continuity cannot be recreated: explicit review
conservatively disarms/cancels and retires that attempt without renewing its death
or owned-time budget. Persisted tower return values do not import cleanup rights.
Preparation-owned boss imports remain blocked until C/D rebind the original owner;
they cannot be silently rebound as a differently owned boss action.

Export includes process owner AND claim owner, acquisition, exact selected gear/
support, manual spawn/death/owned-time/outcome, tower budget/history/selection,
titan spawn obligations/deadlines/cooldowns/pending upgrade, adventure-gold attempt,
boss identity/ordinal/remaining window, OS/native W history/AT targets and finite
action evidence keys. D still must wire these hooks to its validated outer context;
standalone writes are not proof of rollback continuity or universal exactly-once.
