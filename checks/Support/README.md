Run from the repository root. Source includes Support, Beards, receipt availability,
SustainedFocus and its exclusive execution-core invocation. Native runs a separate
compiled production/fixture boundary; the focused selector is not the full suite.
Use shared verification ownership with quiet sources, not direct overlapping builds.
Reports, fail-fast handoff and artifact/evidence limits are in
[Testing And Save Safety](../../docs/testing.md). Internal helpers are not public
entrypoints; neither scope authorizes live actions or deployment.

`SupportChecks` source-links the actual `DiggerAllocation`, `SupportProjection`,
`ActivityPolicy` and JSON registry/parser. It preserves forward-drain adjacent
floating-point boundaries, long limits, duplicate-weight aggregation, backfill,
free diggers, randomized native-ID-order whole-budget conservation and the actual
75-percent policy. Selected Gold changes the budget before planning. Captured
drain/consumption/purchased bounds cannot be counterfeited by request fields.
Exact retained support rejects income/slot/availability/purchased-level loss
without silently resizing. Current/pinned support may exceed the policy fraction,
but never actual income.

`BeardPolicyChecks` runs the same exhaustive pure selector suite as `checks/Beards`.
`BeardReceiptAvailabilityChecks` retains its command name, but now links the REAL
`BeardManager.SelectBeards`, not a fake `RotateBeards`. It checks all eleven
unavailable contexts before the throwing native-cap getter, immediate readiness
retry, current capacity/unlock observations, no mutation, and getter propagation.
There is no selected-executor success stub in either standalone support project.

## Integration Boundary

SustainedFocus links real `Main.Execution`, `Main.CustomFocus` (the selected setup
actuator), `Main.CustomSetup`, `Main.CustomBeards` and shared projection/resource
sources. Existing fixture leaves supply native support/gear data and effects;
its `BeardManager` is a selection-data boundary, NOT the pure selection oracle.
The real native `Main.Support` controller/input/partial-receipt boundary is covered
by the coordinator-owned compiled PresetIntegration checks, not by SustainedFocus's
data-only native leaves. No new fake executor or legacy writer was added.

The full SustainedFocus runner now invokes `ExecutionCoreChecks.Run()` once, as
does its exclusive `--execution-core` path. The beard group no longer separately
invokes its support subgroup, so neither invocation duplicates the core assertions.
The core group includes resource/settings, selected-support authority and the shared
nineteen-case hard-prerequisite matrix. ActivityPolicy integration references this
same source-linked assembly and shares the matrix, not a fake successor/grant.

## Hard Prerequisite Regression

The historical support handoff implemented the narrow `Main.CustomBeards.cs` fix
below. Earlier supervision assignments are evidence, not instructions to resume
agents or duplicate completed work. Current requirements live in [WIP](../../../wip.md).

Confirmed root causes and fixes:

- Optional-only cache identity omitted hard requirements in cached, invalidated-
  retained and pending selections. Hard sets are now defensively copied,
  deduplicated/sorted and included in the acquisition/cache key. Explicit promotion
  obtains one exact replacement; ordinary/repeated requests reuse that selection.
- CombatPrep returned before checking hard prerequisites, and support claims
  checked active-list membership alone. `RequireCustomHardBeards` reuses the
  existing read-only beard availability observation and verifies native list/flag
  agreement, requested IDs, access, active capacity and Gold's normal-Troll unlock.
  It runs before frozen/cached success and after selected application, before
  accepting the event. Empty optional requests remain frozen with no search/write.
- A stronger pending-promotion timestamp assertion exposed a second cadence bug:
  replacing pending support renewed its accepted minute. Replacement now retains
  the pending minute's original accepted time. Epoch/foreign/known-partial guards
  and current digger selection are unchanged. The narrow read-only beard check
  deliberately does not invoke mutation preflight's unrelated digger/GPS/UI locks.

Fresh red/green evidence: the original nineteen-case matrix failed **16/19** on
the unchanged production source. The first fix passed it; the stronger original-
minute assertion then failed **1/19** (pending promotion). After retaining that
timestamp, the final matrix passes **19/19, 104 assertions** in all three runners.
It includes present frozen positive controls, invalidated-retained/pending/cached
promotions, flag/access/disabled/controller/Gold-unlock/capacity rejection, exact
active and inactive digger preservation, repeat-without-reselection/writes, and
original minute preservation. No failure was skipped or assertion weakened.

ActivityPolicy integration's former compile blocker is migrated: its project now
references the existing SustainedFocus source boundary, preserves metadata/primary
priorities, inspects exact native support/budgets, rejects foreign repair and verifies
real callback authority. Its retired manager slot/unlock loop is covered exhaustively
by the actual pure manager suite. Pure ActivityPolicy and its missing-resource variant
remain independent gates.
