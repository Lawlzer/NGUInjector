# Protected Timing Checks

Run `dotnet run --project checks/ProtectedTiming/ProtectedTimingChecks.csproj` from the repository root. This standalone net8 executable source-links the production scheduler, model and SimpleJSON. It has no game references, packages, persistence files or game access. Build outputs stay in this check project's local `bin`/`obj` folders. Only the model's gear-goal enum dependency is stubbed.

Version-17 plans use this engine by default. There is no timing opt-in or legacy allocator path. The executable reports scenario and assertion totals, prints each failed scenario, and exits nonzero on failure.

## Coordinator Contract

- `ProtectedStageScheduler` is internal, instance-based and constructed without arguments. All API members are internal.
- `Update(CustomPlan plan, double elapsed, double heartbeatSeconds, bool canCredit, Func<int, bool> atReached)` is the only progression operation and the only operation that invokes AT callbacks. Supply rebirth elapsed and a monotonic heartbeat in seconds. A new or structurally changed plan skips its leading unfunded flex rows immediately, initializing the first funded/protected row pending without historical credit or AT evaluation. Skipped rows do not increment `Entry`. If all rows are unfunded flex, `Finished` is true and `StageIndex` is -1: no allocation was selected, so the coordinator must not apply a row or run entry actions.
- `MarkApplied(double elapsed, double heartbeatSeconds)` arms credit only after the selected allocation has actually been applied. A selection change, `Suspend()`, ownership loss, backwards clock or either clock gap greater than 15 seconds disarms it. Reapply explicitly before earning again. Credit uses the smaller clock delta and never transfers to the next selection.
- Read-only properties: `int StageIndex`, `long Entry`, `int Cycle`, `double EnteredAt`, `double StageElapsedSeconds`, `double ExpectedEndSeconds`, `bool ProtectedWorkComplete`, `bool Finished`, `double[] Durations`, `double[] EarnedSeconds`, `bool[] Completed`, `string Reason`. Array getters return defensive copies. Fixed-stage elapsed means earned applied seconds; flex/AT elapsed means wall-clock seconds since entry.
- `static string StructureKey(CustomPlan plan)` and `bool Matches(CustomPlan plan)` do not mutate state. Structural identity includes plan name, ordered fixed/flex/AT kinds, AT targets and loop boundary. Duration/weight/horizon edits preserve progress. Names, focus and allocations are cosmetic. Same-kind row reorders are intentionally positional and cannot be distinguished from edits without persistent row IDs.
- `JSONObject ExportState()` returns a detached state tree. `bool RestoreState(CustomPlan plan, JSONObject root)` is transactional and validates schema, types, finite numbers, index ranges and completion shape, including the finished all-flex/no-selection state. Successful restore is unarmed. Uninitialized state is not restorable. Entry is encoded as an invariant Int64 string because SimpleJSON numbers are doubles. The coordinator must validate the game/rebirth epoch before import; no epoch or disk access exists here.
- The protected gate includes all fixed and AT rows in the current pass, including later rows. An initialized all-flex pass has no protected obligations. Finished runtimes hold the last actually selected allocation; unfunded future flex rows are completed without a new entry/allocation.
- Fixed deadlines start nominally at rebirth zero; subsequent fixed deadlines retain the previous boundary for lateness up to 15 seconds, otherwise use actual entry. AT exit always anchors the next boundary to actual time. Only fixed stages longer than 15 seconds can resync at their stable boundary with at most 15 seconds remaining, and only when the current update earns positive applied time from a previously armed, continuously owned interval with both clock deltas in [0, 15]. Historical earned time alone cannot resync after restore, suspension, ownership loss or a clock gap; applying without a positive credit interval cannot resync either. Interruptions do not rebase the stable deadline, so positive live credit after reapplication can permit resync. Stages lasting 1 through 15 seconds require their entire duration in earned applied time, even after their deadline has passed. AT targets are never forgiven.
- Flex allocation reserves all remaining fixed work, shares the remaining horizon by weight, and freezes the active deadline until a relevant timing edit. Allocation multiplies the pool by remaining weight before division, preserving integral boundaries such as 700 * 35 / 100 = 245 for consistent flooring by snapshots/UI. Extremely large weights fall back to dividing first only to avoid overflow. Editing uses the active row's unserved fraction of its old assignment as its remaining weight. Offline gaps may expire flex, never fixed. Completed rows never rewind on timing edits.
- Loops reset only their suffix and start only before the horizon. A current pass's protected work must finish even after the horizon. Each update starts at most one cycle, leaving its first funded selection pending for the next update so zero-time AT loops cannot spin. A finished scheduler stays terminal until structural reset (or a new instance).
- `bool AllowRepeat { get; set; }` defaults to true. Set it false before `Update` when a raw rebirth trigger is available to prevent new repeat-cycle obligations while still finishing the current pass. This admission policy is ephemeral: it is omitted from sidecar exports and resets to true on successful restore, so the coordinator must set it again before updating restored state. Failed restore leaves the property unchanged.

The executable covers credit continuity, exact 15-second boundaries, full-length shortest stages, mandatory AT, offline gaps, initial/trailing zero-budget flex skipping, tail reservation, frozen flex, multiply-before-divide rounding, timing/structural edits (including late opener edits without historical credit and near-Int32-limit extensions), immutable snapshots, malformed/round-tripped sidecars, finite loops and ephemeral repeat admission. Calls to `MarkApplied` here explicitly model a receipt; they do not prove that an allocator ran.

Run `dotnet run --project checks/SustainedFocus/SustainedFocusChecks.csproj` for real source-linked allocator receipts plus the same production scheduler core. Its minimal coordinator adapter controls rebirth and heartbeat clocks independently, never arms credit while selecting or reading snapshots, and only marks application after `ApplyStage` returns a successful receipt with ownership available. It covers failed/partial applications, slower-clock credit, unarmed cache invalidation preserving earned work, fixed transitions requiring a receipt for each row, actual positive AT completion, CAS duration edits, and byte-for-byte read-only beard/snapshot invariants. Snapshots use mode `stages`. The adapter is not the production coordinator and does not validate game epochs or save checkpoints; compiled `ProtectedTimingIntegrationChecks` own that coverage. Allocation, focus, equipment and beard behavior remain in the source-linked SustainedFocus suite.
