# Black-Bar Checks

These executable checks run the built injector's pure allocation/projection methods and stage serializer via reflection. Blood-goal checks compile the production calculation source directly and cover goal formulas, shared production/unspent blood, cast minimums, paused and reached goals, zero production, overflow, and float percentage boundaries. They do not inject code into the game or alter a save. No test framework dependency is required.

Scheduler checks execute the built production scheduler with data-only character/time fixtures, without Unity constructors or controller calls. They cover scale-invariant equal and unequal weights (including 50, 1, .25, tiny fractions, and subnormal weights), exact boundaries, loop restarts, sequential advancement through a met AT step, rebirth epochs, preservation of stage index/start during Iron Pill and auto-boost tuning, run-state/selection resets, and changed versus unchanged/unselected plan saves. Runtime non-finite weights and overflowing totals fail explicitly; store normalization/rejection is also covered by the ExternalUi checks.

Fight-on-entry checks cover legacy false defaults, serializer/native clones, gear/digger locks, prep/rebirth guards, boss-push start, cache-reload deduplication, single-stage loop re-entry, rebirth reset, pending stage-gear restoration, and unchanged run/rebirth switches. Execution fixtures omit game controllers/inventory so prep logs boundary failures; they verify coordination, not successful live equipment/digger/beard changes or boss combat. ExternalUi checks cover normalized read/save, explicit false, reorder/copy, unknown fields, and rejection of non-booleans without modifying saved JSON.

Iron Pill checks cover actual elapsed one-hour/stage-100 eligibility boundaries, plan opt-out, cooldown lookahead, time-OR-worth targets, game worth rounding/cap, and newest-first ten-cast history retention. Reservation is a magic-only stage overlay: `RIT` first, except `MagicFocus == Wandoos` (including its AT phase), where `WAN,RIT` leads. Remaining priorities keep their relative order without duplicates; explicit `RIT-n` entries are replaced by the single sustainable optimizer-selected ritual. Energy priorities, stage gear, saved arrays, AT targets, stage transitions, and sequential timers remain intact. Quick refresh uses the same allocation boundary; runtime progress remains running and reports effective orders plus `bloodReservedForIronPill`.

Each saving-window entry directly calls the game's `castRebirthSpell()` once before starting its timer. The actual NUMBER API has no positive blood minimum: zero is retained without calling, and positive fractional blood is accepted. It never calls `autoSpell()` or loot/gold casts. Reservation starts only after verifying the pool is zero and NUMBER received the blood; rejected/throwing casts back off without claiming success. Missing/locked Blood Magic production state does not flush or start a new window. Newly produced blood is not flushed on subsequent quick/slow passes. All three automatic spells are off while saving and ordinary goal-based toggles return after cast/cancel.

Targets remain configured saving time OR worth (zero disables a target; both zero attempt immediately when ready). The hard prep deadline is `max(900, CustomIronPillSaveSeconds) + 60` rebirth-clock seconds, including cooldown wait. Thus default, worth-only, and immediate/unavailable-blood attempts yield at 960 seconds; longer configured waits get a 60-second grace. Timeout and failed NUMBER flush yield for 900 seconds before a new attempt. Successful pills impose a 10-second restart guard, even when lookahead exceeds the whole cooldown. Manual rebirth, fight/pre-rebirth preparation, boss push, and ready automatic rebirth preempt saving. Successful automatic casts alone enter history, retaining actual saving duration.

`IronPillReservationChecks.cs` executes compiled production methods and the game's real NUMBER/pill implementations with data-only fixtures. Mono.Cecil replaces only five external rendering boundaries in an in-memory game assembly: the blood menu, its three toggle graphics, and the two-argument tooltip display. No spell, allocation, reservation, scheduler, history, or rebirth policy is replaced. No patched DLL is written to disk. Checks cover one-time entry flush across both loops, fractional/zero blood, exceptions and nonthrowing rejected transfers, minimum/rejected/successful pills, restoration, post-cast same-tick guards, finite timeout/backoff, eligibility/preemption, effective telemetry, stages and sequential AT transitions. The source-linked focus suite additionally runs the real stage/black-bar allocators and BloodMagicOptimizer to verify actual default/Wandoos resource distribution, single-ritual gold consumption, quick refresh, energy equivalence, immutable arrays, AT target restoration, and release back to saved priorities.

Gear checks call the game's real per-item bonus conversions, including boss-effectiveness penalties, rather than comparing raw boost points. They cover the Blue Heart NGU2 456000 = 45.6% versus Ring of Utility NGU 6050 = 60.5% regression, mixed stat tiers, cache freshness, and exact equipment-instance snapshots. Drop Chance, Gold, Energy Cap, and Magic Cap use direct single-stat selection, with distinct IDs and correctly weighted offhands.

Multi-stat search checks compare the production solver against exhaustive small inventories for every goal/fight mode. The exact solver uses a complete greedy/local-swap incumbent, component and weighted AM-GM upper bounds, copy-aware dominance implications, and equivalent-item symmetry pruning; there is no lossy top-N cutoff. Ten-slot fixtures include 50 identical IDs and mixed tradeoff copies. Reported complete scores include feasible heuristic trials and DFS leaves; visited nodes and pruned branches measure search work separately. Runtime reports also include elapsed milliseconds.

Equip checks simulate the entire swap plan before any game mutation, then replay it through the game's data-only Inventory methods. They cover all four-accessory permutations, weapon reversals, same-ID replacements without merging, saved-slot preservation, and full-inventory staging failures. Successful native Unity controller/UI calls still require live verification. A same-ID replacement or equipped-item reordering can require one empty inventory slot; failure is explicit, not a destructive merge or a false success.

Build the injector first, then run from the repository root (adjust the paths for your installation):

```powershell
$msbuild = "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\MSBuild\Current\Bin\MSBuild.exe"
$game = "C:\Gaming\Launchers\Steam\Steam\steamapps\common\NGU IDLE"
& $msbuild "NGUInjector.sln" /t:Build /p:Configuration=Release "/p:GameFolder=$game" /verbosity:minimal
& $msbuild "checks\BlackBarChecks.csproj" /restore /t:Build /verbosity:minimal
& "checks\bin\BlackBarChecks.exe" "$PWD\NGUInjector\bin\Release\NGUInjector.dll" "$game\NGUIdle_Data\Managed"
```

The BlackBar check build restores Mono.Cecil 0.11.4 for its in-memory external rendering substitutes. The game assemblies resolve referenced types and supply data-only fixtures. Live controller formulas, gold spending, UI layout, and real Unity scheduling remain outside these offline checks. The ExternalUi check program additionally covers persisted Iron Pill thresholds/history, patch/reload invalidation, native setting bounds, and the blood/Iron Pill metadata contract.

Offline combat checks run with `dotnet run --project checks/Combat/CombatChecks.csproj`; see [Combat/README.md](Combat/README.md). They source-link custom-adventure routing, the combat manager/helpers, and zone helpers with game/Unity and gear boundary stubs; no production build is needed. Gold-detour checks cover boss 101 at 1017 seconds, no boss-90 cutoff, the exact one-hour boundary, Time Machine gates, success/death restoration and selected-farm return, attempted-target deduplication, higher-zone attempts, pre-entry healing, trash rerolls, active expiry, and busy/failed gear swaps across ITOPOD, fixed-zone, and boost modes. Walderp uses the game's attack IDs 3-6 (regular, strong, piercing, ultimate) and enemy types `waldo1` through `waldo4`/`bigBoss5`; titan zone index 5 is the Beast, not Walderp. Combat coverage includes prompt responses, cooldown reservation, early-form boss-only routing, and avoiding idle-toggle oscillation when strong training is zero. Live Unity timing and real inventory/boost selection still require separate verification.

Gold fixtures keep idle autoattack on and manual attack buttons disabled; completion follows enemy lifecycle, not simultaneous manual attacks. Follow-up checks cover interruption before kill/death bookkeeping, pre-entry retry versus entered/lost-lock deduplication, the real adventure reset helper and same-target attempts after rebirth, and high-boss exclusion of titan zones 44/45 at the 871/897/902 boundaries without adding autokill targets. Ordinary combat readiness is scenario-supplied rather than game-simulated. `pwsh -File checks/Combat/VerifyRegressions.ps1` verifies actual assertion failures against temporary boss-90-cutoff and disabled-death-guard mutants without changing production.

The source-linked NGU allocation/focus suite runs without game assemblies:

```powershell
dotnet run --project checks/SustainedFocus/SustainedFocusChecks.csproj
```

It covers version-16 plan defaults (nine energy weights, seven magic weights; Adventure Alpha/Drop Chance energy and Yggdrasil magic), equal and uneven 2:1 weighted generic groups, capped-share redistribution, completed targets, and ordered outer priorities. Exact integer remainders favor the largest fraction, then ascending index. Pure sharing fixtures accept arbitrary target counts and include zero/negative caps, excluded nonpositive weights, all-zero groups, negative budgets, tiny remainders, `long.MaxValue` budgets, and `int.MaxValue` weights. Test-only `BigInteger` sums verify exact conservation without overflowing. Zero-weight rows are excluded before marking targets visited, so a later explicit `NGU-n` can still allocate them. Generic and singleton transfers also conserve both pools when controller text updates throw.

Energy NGU and All NGU own both resource lanes; Magic NGU leaves energy untouched. Focus checks replace enum-goal changes with live array-weight edits, including NGU fallbacks for Time Machine, Wandoos, Augments/Blood, Advanced Training, and Adventure. They cover value-based array comparison, immediate cooldown/status bypass, same-pass publication, affected-lane snapshots, periodic refresh, stop/toggle release, preparation and partial-save readiness guards, unreadable active plans, and initial activation failures. Malformed `Load` must rethrow, not fabricate a fallback that recalls resources. Sequential timing checks retain real positive AT completion and non-scheduling CAS-edit timer preservation; the old NGU-goal edit is now a weight edit. Legacy JSON migration coverage belongs to the ExternalUi suite.

The source-linked suite stubs game/controllers, gear preparation, logging, and publication; its publication wrapper is not production telemetry. The built-assembly BlackBar checks independently verify the real `GetCustomNguRuntime` wrapper, configured versus applied arrays, per-lane applied flags, and all nine/seven rows with `weight`, actual allocation, and known/unknown buffered caps under `weighted-ngu-buffered-cap`. No live save is changed. Both suites require the production weighted contract to be present; a stale built DLL can still contain the removed enum/API. Live Unity controller behavior and equipment actions remain outside these checks.
